# AutoSync — установка на Windows

AutoSync работает на Windows поверх **Docker Desktop**: всё приложение
(backend, frontend, Celery, PostgreSQL, Redis, LLM) — это Linux-контейнеры,
которые Docker Desktop запускает через WSL2 независимо от хоста. Сам Windows
здесь только оркестрирует контейнеры — внутри Windows напрямую ничего не
устанавливается и не компилируется.

## Требования

1. **Windows 10/11**, 64-bit.
2. **Docker Desktop** — скачать и установить: https://www.docker.com/products/docker-desktop/
   При первом запуске Docker Desktop сам предложит включить WSL2 — согласитесь.
   Дождитесь, пока иконка Docker в трее покажет "Docker Desktop is running".
3. Свободное место на диске: минимум ~15 ГБ (образы + LLM-модель, если
   решите скачать её сразу).
4. PowerShell 5.1+ (идёт в комплекте с Windows) или PowerShell 7+.

## Установка

1. Распакуйте архив `autosync-windows_<версия>.zip` в любую временную папку.
2. Откройте **PowerShell от имени администратора** (правая кнопка на
   Пуск → "Терминал (администратор)" или "Windows PowerShell (администратор)").
3. Перейдите в распакованную папку и запустите установщик:

   ```powershell
   cd C:\путь\до\распакованной\папки
   Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
   .\install.ps1
   ```

4. Установщик спросит:
   - **Каталог установки** (по умолчанию `C:\AutoSync`) — сюда будут
     скопированы файлы приложения, здесь же будет храниться `.env`.
   - **Публичный хост/IP** — адрес, по которому браузер будет обращаться к
     AutoSync. Если сервер доступен только с этого же компьютера — оставьте
     `localhost`. Если к нему будут подключаться с других машин в сети —
     укажите IP или доменное имя этого компьютера.
   - **Порт веб-интерфейса** (по умолчанию `5173`).
   - **Скачать LLM-модель сейчас?** — модель `qwen2.5:14b` весит ~9 ГБ.
     Можно пропустить и скачать позже.
   - **Email и пароль администратора** — пароль можно оставить пустым,
     тогда он сгенерируется автоматически и сохранится в файле
     `INITIAL_ADMIN_CREDENTIALS.txt` в каталоге установки.

5. Установщик соберёт и запустит все контейнеры (`docker compose up -d
   --build`) — первый раз это может занять несколько минут — и в конце
   выведет ссылку на веб-интерфейс.

### Неинтерактивная установка

Для автоматизации все ответы можно передать параметрами и добавить `-Silent`:

```powershell
.\install.ps1 -Silent -InstallDir "D:\Apps\AutoSync" -PublicHost 192.168.1.50 `
  -FrontendPort 5173 -AdminEmail admin@company.ru -AdminPassword "..." -PullModel
```

## Автозапуск

Установщик регистрирует задачу в Планировщике заданий Windows с именем
**AutoSync**, которая выполняет `docker compose up -d` при входе в систему —
это Windows-аналог systemd-юнита из Linux-версии. Обязательное условие:
Docker Desktop должен сам запускаться при входе в Windows (по умолчанию так
и есть после установки Docker Desktop — проверить можно в его настройках,
Settings → General → "Start Docker Desktop when you sign in").

## Проверка, что всё работает

```powershell
cd C:\AutoSync
docker compose ps
```

Все сервисы должны быть в статусе `running`/`healthy`. Логи конкретного
сервиса: `docker compose logs -f backend` (или `frontend`, `celery-worker`,
`llm-service`, `ollama`).

## Обновление

Распакуйте новую версию поверх старой папки-источника и повторно запустите
`install.ps1` из неё — существующий `.env` и данные (Docker-volume'ы) не
затрагиваются, файлы приложения обновятся, контейнеры пересоберутся.

## Удаление

```powershell
cd C:\AutoSync
.\uninstall.ps1          # остановить, файлы и данные сохранить
.\uninstall.ps1 -Purge   # остановить и удалить всё, включая базу данных
```

## Частые проблемы

- **`docker compose` не найден** — обновите Docker Desktop до актуальной
  версии (Compose v2 идёт в комплекте, но в старых версиях мог отсутствовать).
- **Порты заняты** — если `5173`/`5000`/`5432`/`6379`/`8000`/`11434` уже
  используются другими программами, переустановите с другими портами
  (параметры `-FrontendPort` и правки `.env` в каталоге установки: 
  `BACKEND_PORT`, `POSTGRES_PORT`, `REDIS_PORT`, `LLM_PORT`, `OLLAMA_PORT`),
  затем `docker compose up -d --build`.
- **Фронтенд открывается, но не видит backend** — почти всегда это
  неверный `VITE_API_BASE_URL` в `.env` (например, указан `localhost`, а
  сайт открывают с другого компьютера по IP сервера). Поправьте
  `VITE_API_BASE_URL` в `.env` на реальный адрес сервера и выполните
  `docker compose up -d --build frontend` — Vite вшивает этот адрес в
  сборку на этапе `build`, поэтому одной перезагрузки страницы недостаточно.
- **Docker Desktop требует WSL2, а он не установлен** — Docker Desktop сам
  подскажет команду `wsl --install`, после неё нужна перезагрузка.
