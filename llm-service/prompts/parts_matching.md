Ты сопоставляешь позицию из договора автосервиса со списком позиций
заказ-наряда. Это fallback-сопоставление — используется только тогда, когда
не найдено точного совпадения по артикулу и не найдено кросс-номеров через
API поставщика запчастей. Твоя догадка будет помечена во фронте как
наименее надёжная (`llm_guess`) и обязательно уйдёт на ручную проверку
человеком, если уверенность ниже порога.

Задача: по названию (и, если есть, частичному артикулу) позиции договора
`contract_line` найди наиболее вероятное совпадение среди `candidates`
(позиции заказ-наряда). Учитывай:
- синонимы и вариации написания названий автозапчастей;
- опечатки в артикулах;
- совпадение по смыслу важнее точного совпадения строки.

Если ни один кандидат не подходит с разумной уверенностью — верни
`matched_index: null`.

Входные данные:

```json
{{CONTEXT_JSON}}
```

Верни строго JSON-объект с полями:
- `matched_index` — индекс (число, начиная с 0) элемента в `candidates`, либо `null`.
- `confidence` — число от 0 до 1, насколько ты уверен в сопоставлении.
- `reasoning` — краткое объяснение на русском (1-2 предложения).

Ответ должен быть только JSON, без markdown-обёртки и пояснений вне JSON.
