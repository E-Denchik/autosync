Ты сопоставляешь описание работы из заказ-наряда автосервиса со списком
стандартных операций (нормо-часов).

Задача: по `description` найди наиболее вероятное совпадение среди
`candidates` (список операций с полями `operation_name`, `norm_hours`,
`vehicle_make`, `vehicle_model`). Учитывай синонимы и вариации формулировок
("замена диска" = "замена тормозного диска"). Если ни один кандидат не
подходит с разумной уверенностью — верни `matched_index: null`.

Автомобиль из заказ-наряда — `vehicle_make`/`vehicle_model` на верхнем
уровне входных данных. У части (или всех) `candidates` марка/модель может
ОТЛИЧАТЬСЯ от него — это значит, что для точной марки в справочнике пока
ничего не завели, и кандидаты подобраны из справочника по ДРУГИМ маркам
как ориентир, а не гарантированное совпадение. В этом случае:
- Совпадение по марке/модели — как обычно, самый надёжный вариант.
- Кандидата с ДРУГОЙ маркой бери только для операций, время которых по
  сути не зависит от конкретной марки/модели (плановое ТО, замена
  расходников вроде масла/фильтров/колодок, диагностика, шиномонтаж и
  т.п.) — для них норма часов у разных марок обычно близка.
- Для работ, зависящих от конкретной марки/модели (снятие/разборка узлов,
  кузовной ремонт, специфичные для платформы операции) кандидата с другой
  маркой НЕ предлагай, даже если название операции похоже — верни
  `matched_index: null`.
- Если решил использовать кандидата с другой маркой — снижай `confidence`
  (не выше 0.6) и явно укажи в `reasoning`, что норма перенесена с другой
  марки/модели.

Входные данные:

```json
{{CONTEXT_JSON}}
```

Верни строго JSON-объект с полями:
- `matched_index` — индекс (число, начиная с 0) элемента в `candidates`, либо `null`.
- `confidence` — число от 0 до 1.
- `reasoning` — краткое объяснение на русском (1-2 предложения).

Ответ должен быть только JSON, без markdown-обёртки и пояснений вне JSON.
